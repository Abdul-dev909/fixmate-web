Section 3: Operating Rules

Rule Category 1. Exact Condition 2. Where User is Told 3. Application Response 4. Boundary Case
Availability / Capacity
(Rule 1: Slot Capacity)		 Each appointment slot has a capacity limit: maxBookingsPerSlot. Remaining spots = max - currentBookings[slot]. If remaining <= 0, slot is full. Directly on the slot selection pills on /services/:id with live count badges ("2 left", "1 left", "Fully Booked"). Disables saturated slot buttons, renders "Fully Booked" in red, and blocks adding to cart if an invalid slot is targeted. Boundary: Exactly 1 booking left. Result: Button remains selectable with an explicit warning "1 left" and locks upon reaching limit.
Eligibility / Compatibility
(Rule 2: Sector Coverage)		 A booking is eligible only if customer's sector is included in service.areasCovered. On /services/:id (coverage list & live sector validator) and at /checkout during sector selection. Displays green "✓ Service is available in Sector X" if valid; shows red "✕ Service does not cover Sector Y" and blocks submission if invalid. Boundary: Periphery sector like I-14 which is covered by heavy services (moving, tank cleaning) but excluded by local repair. Properly caught at checkout.
Pricing / Fulfilment
(Rule 3: Fee Waiver Threshold)		 Orders incur standard 5% service fee. If subtotal >= PKR 10,000, the 5% platform fee is completely waived (Fee = PKR 0). In the calculated summary sidebar on /cart and /checkout, with an interactive threshold reminder banner. Dynamically adjusts the total price without reload. When >= 10,000, displays "FREE / Waived" badge and saves 5% of order. Boundary: Subtotal exactly PKR 10,000. Result: Service fee drops from PKR 500 to PKR 0 (Free Service Waiver triggered).

Section 4: Reference-Site Investigation (HomeGenie)

Reference Website URL: https://homegenie.lovable.app | Domain: Home Services & Repairs

Problem 1: Broken Dark Mode Toggle Button

  • Task User is Trying to Complete: Toggle the website appearance between light and dark modes for readability in low-light environments.
  • What Goes Wrong: Clicking the moon/sun icon button does not trigger any theme stylesheet changes or persistent state update; the site remains stuck in light mode.
  • Business Consequence: Accessibility barrier causing eye strain for night-time users, leading to quick site abandonment and poor impression of technical quality.
  • How FixMate Addresses It: Implemented a central ThemeContext managing a data-theme attribute on the root <html> element, persisted in localStorage, with CSS variables across all components ensuring smooth, zero-flash transitions.

Problem 2: Service Cards Conceal Provider Details on Click

  • Task User is Trying to Complete: Review assigned provider credentials, track record, and verification status before booking someone into their residence.
  • What Goes Wrong: Service cards on HomeGenie provide no working provider details upon clicking, hiding technician identity behind a non-responsive interface.
  • Business Consequence: Loss of customer trust and high checkout abandonment; homeowners are hesitant to book unverified unknown contractors.
  • How FixMate Addresses It: Renders provider firm name, verified badge, and years of experience directly on every service card. Furthermore, the /services/:id detail route features a dedicated Provider Profile section with direct helpline and warranty info.

Problem 3: Homepage Search Bar Fails on Vague / Cross-Category Queries

  • Task User is Trying to Complete: Search using intuitive problem terms such as "ac cleaning", "leak repair", or "pest".
  • What Goes Wrong: HomeGenie's search executes strict exact title/category matching. Searching "ac cleaning" yields 0 results because AC is categorized under appliance repair and cleaning is a separate bucket.
  • Business Consequence: Customers falsely conclude the platform does not service ACs or pipe leaks, abandoning the platform for competitors.
  • How FixMate Addresses It: Implemented a tokenized fuzzy search utility (src/utils/search.js) scoring matches across title, category, description, and tags simultaneously, supplemented by quick-search chips.

Section 5: Frontend Architectural Decisions (DECISIONS.md Summary)

Decision Decision Chosen Alternative Considered Reason Tradeoff
1. Theme Persistence (State & Interaction) React ThemeContext setting data-theme on root HTML element and saving to localStorage. Class-based toggling on individual React components. Guarantees 100% theme consistency across current and future views with zero flash on reload. Requires discipline with semantic CSS variables rather than hardcoded hex colors.
2. Provider Transparency (Hierarchy & Layout) Inline provider badges on cards + comprehensive Provider Profile Card on /services/:id. Modal dialog appearing on card click. Establishes immediate trust in home services without unnecessary modal navigation layers. Consumes vertical card real-estate, requiring compact responsive styling on mobile (390px).
3. Multi-Token Search (Interaction & Filtering) Tokenized scoring algorithm matching across names, tags, categories, and descriptions with quick chips. Strict title substring matching or third-party server index. Accommodates natural customer queries ("ac cleaning") without requiring backend server overhead. Multi-token JS scoring scales efficiently for hundreds of records; larger catalogs need indexing.

Section 6: Implemented Application Journey

The deployed FixMate application delivers a complete, cohesive 7-step customer journey:

  1. Browse: Home (/) and Catalog (/services) display 12 services with category tags, pricing, and verified provider badges.
  2. Search & Narrow Down: Debounced fuzzy search with live counter, category filter dropdown, and 5-way sorting (Price Asc/Desc, Rating, Name, Popularity).
  3. Open Details: Dynamic route /services/:id showcases complete description, provider profile, and covered sectors.
  4. Build & Change Selection: Slot capacity selection (Rule 1) and numerical quantity control (1–6 boundary).
  5. Review Summary: /cart displays dynamic item list, quantity modification (+/-), removal, subtotal, and 5% fee waiver check (Rule 3).
  6. Complete Form: /checkout contains a controlled React form validating name (min 3 chars), Pakistani phone regex (03XX-XXXXXXX), sector coverage (Rule 2), and street address.
  7. Confirmation: /confirmation generates booking reference (#FXM-XXXXXX), presents full customer breakdown, clears cart, and offers printable receipt.
